Project: SecureShieldAI
======================

Overview:
---------
SecureShieldAI is a security-focused project designed to simulate and monitor attacks using honeypots, log and analyze suspicious activities, and provide a dashboard for administrators. The project is organized into backend and frontend components, with supporting scripts, documentation, and configuration files.

Main Components:
----------------

1. Backend (Python, Flask):
   - Located in the `backend/` directory.
   - Handles honeypot services (FTP, SSH, generic), logging, database operations, API endpoints, and admin routes.
   - Key files:
     - `run.py`: Entry point to start the backend server.
     - `app/`: Contains the main application logic, including:
       - `honeypot_ftp.py`, `honeypot_ssh.py`, `honeypot.py`: Simulate vulnerable services to attract attackers.
       - `server.py`: Main server logic, likely initializes Flask and routes.
       - `routes/`: API, admin, and login route handlers.
       - `middleware/`: Request interception and processing.
       - `logger/`: Attack logging and log formatting.
       - `utils/`: Helper utilities for alerts, IP tracking, time, and header parsing.
       - `config/`: Settings and SSL configuration.
     - `database/`: Database connection, models, and schema (likely SQLite or similar).
     - `certificates/`: SSL certificates for secure communication.
     - `logs/`: Stores log files generated by the backend.

2. Frontend Dashboard (React + Vite):
   - Located in the `frontend-dashboard/` directory.
   - Provides a web-based dashboard for monitoring attacks, viewing logs, and statistics.
   - Key files:
     - `src/`: Main source code for the React app.
       - `components/`: UI components (AttackTable, ChartPanel, Navbar, StatsPanel).
       - `pages/`: Dashboard and Logs pages.
       - `services/api.js`: Handles API requests to the backend.
       - `styles/`: CSS for styling the dashboard.
     - `public/`: Static assets.
     - `index.html`, `main.jsx`: App entry points.
     - `package.json`: Project dependencies and scripts.

3. Fake Webpages:
   - Located in `fake-webpages/`.
   - Contains decoy HTML pages (admin, config, database, login) to lure attackers and monitor their interactions.

4. Scripts:
   - Located in `scripts/`.
   - Utility scripts for SSL generation, log monitoring, and server startup.

5. Documentation:
   - Located in `docs/`.
   - Contains screenshots and other documentation resources.

6. Tests:
   - Located in `tests/`.
   - Contains test scripts for backend components (logger, server, etc.).

7. Docker & Deployment:
   - `docker-compose.yml`: Orchestrates multi-container deployment (backend, frontend, database, etc.).
   - `backend/Dockerfile`: Dockerfile for backend service.

How It Works:
-------------
- The backend runs honeypot services to attract and log malicious activity.
- All requests and suspicious actions are logged and stored in the database.
- The frontend dashboard fetches data from the backend via API endpoints and displays real-time statistics, logs, and attack information.
- Decoy web pages are served to further attract attackers and monitor their behavior.
- SSL is used for secure communication.
- The project is containerized for easy deployment using Docker Compose.

Key Features:
-------------
- Multi-protocol honeypot (FTP, SSH, web, etc.)
- Centralized logging and alerting
- Real-time dashboard for monitoring
- Decoy web pages for additional attack surface
- Secure (SSL-enabled) communication
- Modular and extensible codebase
- Automated deployment with Docker

Development & Usage Notes:
-------------------------
- Backend dependencies are listed in `backend/requirements.txt`.
- Frontend dependencies are managed via `frontend-dashboard/package.json`.
- SSL certificates should be generated and placed in `backend/certificates/`.
- Database schema and connection logic are in `backend/database/`.
- To run locally, use the provided scripts or Docker Compose.
- Tests are in the `tests/` directory and can be run to validate backend functionality.

Security Considerations:
------------------------
- Do not expose real admin credentials or sensitive data in decoy pages.
- Ensure SSL certificates are valid and not committed to public repositories.
- Regularly review logs and alerts for suspicious activity.
- Keep dependencies up to date to avoid vulnerabilities.
